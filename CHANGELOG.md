# Changelog

Все заметные изменения проекта фиксируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
версионирование — [Semantic Versioning](https://semver.org/lang/ru/)
(`MAJOR.MINOR.PATCH`: MAJOR — ломающие изменения, MINOR — новая функциональность
с обратной совместимостью, PATCH — исправления ошибок).

Версия приложения берётся из ближайшего Git-тега автоматически при сборке
(см. `docker-compose.yml` → `build.args.APP_VERSION` и `make version`) —
сам файл `CHANGELOG.md` не влияет на то, что покажет `/health` или Swagger,
он служит читаемой историей для людей.

## [Unreleased]

Изменения, которые попадут в следующий релиз, но ещё не помечены тегом.

### Добавлено

- Учебный маршрут `/learning` с 48 микро-уроками в пропорции 5/95, созданием
  starter-файла, переходом в IDE и персональным прогрессом.
- Структурированная оценка попытки: baseline, статическая политика, назначенные
  контролируемые мутации, JUnit-метрики и история критериев в БД.
- Кабинет `MANAGER` `/learning/manage` с агрегированным прогрессом учеников.
- Alembic-миграции с безопасным обновлением существующей legacy-базы и проверкой
  соответствия ORM последней ревизии. Архивные
  `lesson_progress` и `lab_submissions` сохраняются, а legacy-индекс
  зачислений нормализуется без перестроения таблицы.
- Защита IDE API авторизацией, cross-site POST для cookie-сессий и базовые
  security headers; локальные порты Docker привязаны к `127.0.0.1`.
- Учебный контент seed полностью переработан: 50 курсов объединены в 10
  треков «от простого к сложному» (основы → pytest → HTTP/API → API полигона →
  Playwright → UI полигона → данные и интеграции → контракты и надёжность →
  безопасность/RBAC → CI/CD). Описания курсов содержат примеры кода и ссылки
  на практические задачи; ~100 экзаменов и ~500 вопросов всех типов с валидными
  ответами комбинируют теорию автоматизации и знание мишеней полигона.
- `python -m app.seed --reset-content` и `make seed-reset`: пересоздание
  учебного контента с сохранением пользователей.
- Fail-fast проверка конфигурации: приложение отказывается стартовать в
  `ENVIRONMENT=production` с заведомо небезопасным `SECRET_KEY`-заглушкой.
- HEALTHCHECK для сервиса `app` в Dockerfile и docker-compose.yml — статус
  контейнера отражает реальную готовность `/health` (`docker compose ps`,
  `docker compose up --wait`).
- Резервный GitHub Actions workflow `.github/workflows/backend-ci.yml`
  (ruff + pytest с coverage gate 70%) — быстрый фидбек на push/PR параллельно
  с локальным Jenkins.
- Маршрут обучения в `student_tests/README.md`: порядок освоения задач от
  basic к advanced с указанием образцов.
- Page Object каркас для UI-задач: `student_tests/ui/pages/`
  (`BasePage`, `LoginPage`) с готовыми локаторами страницы входа.
- Работающие обучающие примеры: `api/test_example_api_patterns.py`
  (параметризация, изоляция данных, CRUD, ETag) и
  `ui/test_example_page_object.py` (Page Object, позитивный и негативный
  сценарий входа).
- Трекер прогресса `make progress` (`tools/check_progress.py`) — сверяет файлы
  решений в `student_tests/` с каталогом задач и показывает процент покрытия.
- Каталог практических задач: API, контракты,
  безопасность, Playwright UI, БД, файлы, WebSocket, надёжность и CI.
- Интеграция с локальной IDE: настройки VS Code (тест-эксплорер, задачи,
  дебаггер, рекомендуемые расширения) в `.vscode/`.
- Watch-режим `make watch-api` / `make watch-ui`: автоперезапуск учебных
  тестов при сохранении файла (pytest-watcher + обёртка `tools/ptw_runner.sh`).
- Встроенная веб-IDE (code-server, http://localhost:8443): VS Code в браузере
  с готовым окружением ученика — Python 3.13, зависимости student_tests,
  Chromium для UI-тестов, Testing-панель, дебаггер и watch-режим. Сервис
  объявлен в docker-compose.override.yml и поднимается только локально;
  Jenkins-сборки его не затрагивает.
- Страница IDE в интерфейсе приложения (/ide): редактор кода для
  student_tests с сохранением, кнопкой запуска тестов и поиском локаторов —
  все data-testid выбранной страницы с копированием готовых селекторов
  `page.get_by_test_id(...)` и живым предпросмотром. Доступна в
  development/test окружениях; эндпоинты `/api/ide/*` в production отвечают 404.
- Создание новых файлов решений прямо из IDE (/ide): вводите имя вида
  `api/test_my_task.py`, получаете готовый скелет теста, сохраняете и
  запускаете без выхода из браузера. Новые файлы ограничены каталогами
  api/contract/integration/ui; дубликаты отклоняются (409).
- Удаление файлов решений из IDE: кнопка ✕ у каждого файла в списке
  (DELETE /api/ide/file) с подтверждением; при удалении открытого файла
  редактор сбрасывается. Закоммиченные файлы восстановимы через git checkout.
- Импорт axe-playwright-python в student_tests/conftest.py стал опциональным:
  окружения без пакета просто пропускают accessibility-тесты.
- Детерминированные мишени `/api/practice/*`: HTTP-статусы, варианты схем,
  CRUD, пагинация, идемпотентность, ETag/If-Match, async polling, files,
  cookies, redirects и webhook recorder.
- UI-мишень `/practice/components` для форм, scoped-локаторов, динамического
  DOM, iframe, Shadow DOM, dialog и новой вкладки.
- Изолированный контур `student_tests` с общими фикстурами, markers, шаблонами
  и адресным teardown по `X-Test-Run-Id`.
- RU/EN-локализация серверного интерфейса и явный переключатель языка.
- Прямой сброс пароля без email для development-стенда с хешированием нового
  пароля, аудитом и ограничением частоты попыток.

### Изменено

- Образ приложения собирается с непривилегированным пользователем `appuser`
  вместо root; директории под именованные volumes (аватары, история качества)
  предварительно созданы с нужным владельцем.
- Убраны из репозитория файлы IDE (`.idea/`), `.gitignore` дополнен; удалена
  слитая ветка `codex/ui`.
- Jenkins разделяет эталонные и пользовательские API/UI-тесты, автоматически
  собирает новые `student_tests/**/test_*.py` и сохраняет результаты в Allure.
- `ADDING_TESTS.md` описывает реальный процесс IDE → Git → Jenkins → Allure.
- Восстановлен учебный маршрут, а прогресс теперь рассчитывается по фактическим
  запускам вместо наличия файла или результата теоретического экзамена.
- Выбор языка заменён на компактный переключатель RU/EN с немедленным
  применением без отдельной кнопки.

## [0.1.0] — 2026-06-20

Первый зафиксированный срез проекта. Версия `0.1.x` означает, что проект
ещё активно дорабатывается и API/схема БД могут меняться без отдельного
процесса депрекации — это нормально для `0.x` по семантике SemVer.

### Добавлено

- Базовая платформа: FastAPI + SQLAlchemy 2.0 + PostgreSQL, серверный
  веб-интерфейс на Jinja2, JWT-аутентификация, RBAC (ADMIN/MANAGER/USER).
- Сущности: курсы, экзамены с вопросами (SINGLE/MULTI/TEXT/DND), уведомления,
  записи на курсы, журнал аудита.
- Режим Testing Playground (искусственные задержки и ошибки 500) для
  тренировки устойчивости автотестов.
- Полный CRUD для администратора: курсы, экзамены с вопросами, уведомления
  (адресные и широковещательные), управление пользователями (роли,
  активация/деактивация).
- Seed-данные: 50 курсов, ~100 экзаменов, ~500 вопросов, демо-пользователи.
- Примеры тестов: pytest (API, включая RBAC), Playwright (E2E).
- CI/CD: Jenkins (Pipeline) + Allure для визуализации результатов тестов,
  оба в общем `docker-compose.yml`.
- Документация: `README.md`, `ARCHITECTURE.md` (как расширять проект),
  `ADDING_TESTS.md` (как добавлять тесты, чтобы они шли в Jenkins/Allure).
- Версионирование приложения от Git-тегов (`git describe`), видна в Swagger,
  `/health` и подвале UI.

### Известные ограничения

- Нет механизма миграций БД (Alembic) — описано как осознанное упрощение
  в `ARCHITECTURE.md`, раздел 2.
- `Jenkinsfile` — рабочая отправная точка, требует подстройки под конкретное
  Jenkins-окружение (см. комментарии в начале файла).
