## P0. Приоритет 1 — самые востребованные классы проверок

### 1. Дашборд практики — выполнено в `/learning`
Прогресс теперь хранится по пользователю и подтверждается запусками и критериями.
Перенести его в UI и расширить:
- **Матрица прогресса по каталогу**: каждая задача из `/api/practice/catalog` со статусом
  «есть файл решения / есть тесты / последний результат прогона» (см. п. 6);
- фильтры по трекам и уровням (basic/intermediate/advanced), процент закрытия трека;
- **кнопка ▶ Запустить** прямо из карточки задачи (переиспользует `/api/ide/run`);
- история последних прогонов (файл, дата, exit code, время);
- мини-гайд маршрута обучения из `student_tests/README.md` с чек-боксами;
- быстрые ссылки: IDE, Allure, Jenkins, Swagger.
Бэкенду достаточно трёх эндпоинтов: `GET /api/ide/progress` (каталог + файлы + счётчик
тестов), `GET /api/ide/runs` (история), `POST /api/ide/run` — уже есть.

### 2. IDOR / Broken Access Control (классика API-безопасности)
Мишень: доступ к чужому ресурсу. Например, `GET /api/practice/resources/{id}` без
заголовка X-Test-Run-Id при мутации `idor-enabled` возвращает чужие записи (сейчас
возвращает пустой список). Тест обязан поймать утечку. Дефект включается тем же
механизмом мутаций — учимся писать тесты на изоляцию аренды данных (multi-tenancy).

### 3. CSV/экспорт: Content-Disposition, кодировки, BOM
`GET /api/practice/resources/export.csv` (+ мутации «UTF-8 без BOM», «; вместо ,»).
Проверки: имя файла в заголовке, кодировка, число строк = total, экранирование запятых
в полях. Класс production-проверок, которого нет.

### 4. Вебхуки с HMAC-подписью
Рекордер уже есть; добавить вычисление подписи `X-Signature: hmacsha256(body, secret)`
(+ мутация «подпись не проверяется»). Тест: отправить событие, проверить подпись,
повторить тот же payload (replay) — ожидаем отказ.

### 5. Курсорная пагинация
Offset-пагинация есть; добавить `GET /resources/cursor?cursor=...&limit=...` с
непрозрачным токеном. Класс проверки: стабильность страницы при вставках между
запросами (offset «прыгает», курсор — нет).

### 6. История прогонов student-тестов в БД — выполнено
`/api/ide/run` сохраняет `practice_runs`, критериальные результаты и
`practice_progress`; IDE API требует авторизованного пользователя.

### 7. Security headers + JWT-мутации
- `GET /api/practice/headers` возвращает текущие security-заголовки ответов
  (CSP, X-Content-Type-Options, X-Frame-Options, HSTS);
- мутация `security-headers-removed` — тест ловит их отсутствие;
- мутация `jwt-skip-expiry` — тест ловит, что просроченный access-токен работает.

## P1. Приоритет 2 — расширение классов

### 8. UI-таблица с серверной сортировкой/фильтром/пагинацией
Страница `/practice/table`: сортировка кликом по заголовку, текстовый фильтр с
дебаунсом, пагинация, пустое состояние и skeleton-loader. Закрывает самый частый
корпоративный UI-кейс, которого нет.

### 9. Drag-and-drop сортировка списка
`/practice/dnd`: перестановка элементов мышью и клавиатурой (a11y!), сохранение
порядка на сервере (PUT order). Проверка: порядок сохраняется после перезагрузки.

### 10. Загрузка файлов через UI с прогрессом
Drag-n-drop зона + прогресс-бар + ошибка «файл слишком большой» + скачивание
результата. Связка UI+API на файлах, которой нет в UI-каталоге.

### 11. PATCH и массовые операции
`PATCH /resources/{id}` (частичное обновление), `POST /resources/bulk` (массив
операций, частичный успех 207). Класс проверок: частичные ответы и атомарность
пакетов.

### 12. Демонстрация инъекций (безопасно)
Мишень «поиск» с мутацией `sql-injection-enabled` (конкатенация строки вместо
параметризации) и поле, отражающее ввод при мутации `xss-reflected`. Тесты учатся
проверять, что инъекция НЕ работает; мутация подтверждает чувствительность проверок.
Никакого реального вреда — данные живут в namespace ученика.

### 13. Unicode и локализационные крайние случаи
Ресурс с полями, принимающими эмодзи, RTL-текст, составные символы; проверки
round-trip, длина в символах vs байтах, сортировка по локали.

### 14. Часовые пояса
Поля created_at: тест проверяет формат ISO-8601 с offset и отображение в UI для
разных TZ (мутация `tz-utc-instead-local`).

### 15. GraphQL-мишень (опционально)
Мини-схема поверх ресурсов: query/variables/ошибки — отдельный класс клиентов,
который сейчас не покрыт совсем.

## P2. Приоритет 3 — по мере роста

- **Visual checks**: Playwright-скриншоты базовых страниц + мутации стилей;
- **SSE** (`text/event-stream`) как альтернатива WebSocket-фиду;
- **OAuth2/OIDC flow** через WireMock (authorization code с мок-IdP);
- **Circuit breaker** на внешних вызовах (после N ошибок — быстрый отказ);
- **Большие payload'ы** (10 МБ, chunked) для тестов таймаутов и памяти;
- **Email-мишень**: mock-SMTP контейнер, проверка письма сброса пароля (тема,
  ссылка с одноразовым токеном, истечение ссылки);
- **GitHub Actions для e2e** (сейчас только backend-джоба) и pre-commit hooks (ruff);
- **Экспорт отчётов** (PDF/HTML) с проверкой структуры документа;
- **Флейк-статистика** на дашборде: % нестабильных тестов по истории прогонов (п. 6).

## Не делать (осознанно)

- Реальные сторонние сервисы (почта, платёжные шлюзы) — только WireMock:
  детерминизм важнее реализма.
- Нагрузочные мишени внутри основного стека — Locust уже есть, гонять его против
  отдельного инстанса, чтобы не смешивать результаты функциональных прогонов.
- Браузерные расширения, нативный push, Bluetooth/WebGL — вне досягаемости CI
  и учебных целей.
